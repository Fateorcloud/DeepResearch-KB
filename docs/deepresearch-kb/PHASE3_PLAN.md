# Phase 3 工作计划与验收门槛

状态：进行中，不沿用 Phase 2 的“最小闭环完成”作为本阶段完成证明。

1. 冻结 Phase 2 最后导入即 active 的选择行为，增加迟到历史文档/未来生效案例。
2. 区分 ingested_at、updated_at、effective_at；时间一律带时区，统一 UTC。
3. 支持 current / as_of / include_superseded / include_deprecated；先选择版本，再做相关性检索，避免旧版因更匹配而泄漏。
4. SQLite migration 保留原文、chunk IDs、历史引用；旧数据缺少有效时间时明确标注推断，不假装已知。
5. authority 仅在合格证据之间排序，不让高权威过期版本越过时间过滤。
6. Evidence 与报告记录状态、生效时间、选择理由；词法与向量入口使用同一选择规则。
7. 冲突仅提示，不裁决；时间不同不直接算事实矛盾。事实冲突检测须说明覆盖范围和 unknown。
8. CLI/研究参数、固定对照评测、失败日志、验收文档齐全后，才宣告 Phase 3 完成。

默认语义：历史查询是依据目前保存材料重建当时有效事实，不是重建“当时已入库的信息”。
current 使用查询时间；as_of 必须显式传时间。生效截止、废弃时间采用半开区间。
最新有效版本被废弃时默认不回退旧方案；显式 include_deprecated 才显示。
同文档相同生效时刻以较大版本号为后续修订，不以 authority 改写时间顺序。

本轮先实现与存储分离的版本选择规则并测试；暂不改变现有查询默认行为。
